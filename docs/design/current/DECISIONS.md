## 2026-10-11：Q39.3.d 路网以连线表示相通

## 2026-10-11：跳夜不加速，后台按数值结算并落到该在的位置

- 用户要求先核实“睡觉期间 tick 是否在加速跑”，并约定：若为否，跳夜直接结算数值并把居民送到该在的地方；若为是，则须逐帧补跑。
- 助手按本版源码（MC 26.1.2 的 clock 系统）核对，结论为**不会加速**：`ServerLevel.tick()` 在满足睡眠人数且深度睡眠时把时钟**一步**移到 `ClockTimeMarkers.WAKE_UP_FROM_SLEEP` 并唤醒全体；`SleepStatus.areEnoughDeepSleeping` 以 `isSleepingLongEnough`（sleepCounter ≥ 100 刻，约 5 秒）为准；`ClockTimeMarker.resolveTimeToMoveTo` 对周期 24000、`wake_up_from_sleep` 在第 0 刻的标记是“前进到下一个第 0 刻”，即跳到黎明；时钟速率默认为 1，睡眠期间没有提速逻辑，只有 NeoForge 的 `/neoforge day` 或模组能改速率。
- 按用户给的条件分支执行：采用“直接结算数值＋把居民送到该在的地方”，不做逐帧补跑。
- 待查：时钟速率被改成非 1 时需重新核对；证据属静态源码核对，未在游戏内实测。
- 已同步居民生活专题与 Q 清单；属设计确认，未实现、未验证。
