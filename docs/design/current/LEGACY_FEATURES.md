# 长期设计保留项

> 原设计来源：[旧 SPEC 完整归档](../../archive/2026-10-07/docs/design/SPEC.md)。本轮仅整理，不整体否定旧 SPEC，也不把未重新讨论的旧设想升级为当前实施范围。

## 保留的产品方向

2026-10-11 更新：用户已重新明确角色自主生活、社交和故事是产品核心，玩家以管理者兼成员身份参与并可组建家庭。因此这些方向本身不再只是长期保留项；下表的具体旧机制、数值与继承规则仍未重新确认。参见总览及 Q39。

第一人称参与城镇、居民有名字和私产、真实采集建造、长期关系与城镇故事。原文“所有事都可现场看到”“不使用建筑菜单”不能解释为禁止已确认的后台模拟或剧本／招标 UI。

## 按系统保留的旧设计

| 系统 | 尚有价值的旧内容 | 与新体系的接缝／待讨论项 |
|---|---|---|
| 身份与技能（§12.1、12.4） | 名字池、量化特质、13 项技能，Lv0 可学、Lv-1 由特质锁定；出生 10 点、升级成本递增的旧方案 | Q30：TLM 女仆载体与居民成长，技能效率／副产物如何进入工时与价值；旧村民外观不能当当前实体实现 |
| 心情、休息、健康（§12.2） | 多因素心情、睡眠恢复、环境触发病症 | Q31：具体速率、疾病与治疗参数；已确认饥饿不致死、生理需求优先，旧饿死和工作时间禁睡退出 |
| 社交（§12.3） | 单向好感、七级关系、冲突记忆、通过仪式成为伴侣 | Q32：事件幅度、衰减、仪式条件、记忆期限；伴侣优先继承与管理员死亡充公冲突，不能照抄 |
| 声望与迁出（§9） | 领地声望和个人声望分开、对行为作出反应、逃离前处置资产 | Q33：声望阈值、产权侵害赔偿、迁出时委托和产业去向 |
| 征召与战斗（§10、12.6） | 驻守／征召，卫兵巡逻、民兵换装、普通居民躲藏，警报及战后恢复 | Q34：工资来源与任务中断、征召资格、视野和躲藏参数；不得继续使用贡献点工资 |
| 死亡与复活（§11） | 墓碑、稀有复活道具、纪念与哀悼 | Q35：复活窗口、代价、身份恢复和已经充公的资产；产业死亡处置优先用当前规则 |
| 功能区与空间所有权（§5–7） | 家具锚点产生功能区、非全房间扫描；物品／方块／位置与所有者的关系 | Q36：是否保留每栈 Owner 标签、功能区半径、地皮高度与重叠；新 MQ 财产挂件不是旧 Owner 标签的自动实现 |
| 建筑模板（§12.7） | 旧选定方向为结构规则模板：居民选户型、参数化材质、建筑工逐块施工、居民布置内部家具 | Q37：8×8 地皮约束、模板格式与扫描参数化、结构要求、屋檐越界、多层；不能将此旧方向标为本轮新确认 |
| 事件（§12.5） | 条件触发＋定时随机；袭击、商队、流浪者加入、抱怨；个体闲聊不等于宏观事件 | Q38：事件 API、触发参数与营地增长；外部商队按当前概率到访规则，不连续模拟旅程 |

## 不再沿用的旧基础

贡献点实物锚定、个人负债与仓库透支、制作价 1.2M／人工费 0.2M、饥饿致死、6 点起床、产业常规换管理员、死亡完成货退供货者、四仓并列。对应替代规则见 [冲突表](../../planning/CONFLICTS.md)。

旧数值表中的 PLACEHOLDER 不是默认配置。仍有价值的例子保留在归档，需要开发时回查；Q30–Q38 统一管理这些未完成系统，不要求现在逐一回答所有数值。
