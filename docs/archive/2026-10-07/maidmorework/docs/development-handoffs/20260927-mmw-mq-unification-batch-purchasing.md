## 背景

MQ 完成委托统一化改造：订单不再有受益中心概念；发布者/接取者统一为 QuestActor 身份；
材料单归属 = 发布它的女仆（管理员本人）；新增按发布者批量撤单接口；
`MaterialBeneficiaryRegistry` 等旧接口移除。

同轮主人拍板：MMW 材料采购改为**批次采购**模型——每次只发固定一批，不管当前缺口多少；
有活单在途不追加；单交割完（交付并领回）后仍缺就再发；多余材料进中心仓库当库存。

## 本轮实施内容

### 1. MQ 统一化编译适配

- `MqBridge`：委托模式改读 `MaidQuestCommonConfig.COMMISSION_MODE`（女仆附件已移除）；
  新增按发布者撤单桥方法（调用点前置 `ModList.isLoaded("maidquest")` 保护）。
- 取消事件：`claimedBy()` → `claimant()`（收回认领者身上带标记的成品）。
- 材料接口：`requestMaterial` 去掉受益中心参数；`materialOrdersFor` 改传管理员 UUID；
  `claimMaterial` → `claimOutput`；删除 `MaterialBeneficiaryRegistry` 注册。
- 供货资格：`canSupply` 改为按材料单 `publisher` 反查"是否某工坊管理员"；
  林场认单（`tickClaim`）同样按发布者判定。

### 2. 批次采购（核心）

- 来源标签：中心 + 材料 + 订单/备货，稳定唯一，与工程无关；材料指纹为候选物品 ID 排序拼接。
- 批次量：`max(1, 堆叠上限 / 4)`（64→16、16→4、不可堆叠→1）。
- 在途判定：该材料有活单（未交付 + 已交付托管未领）时整批等待，不追加、不按量抵扣；
  活单领回后仍缺则重新登记下一批。
- 每笔缺口登记后由管理女仆到板发布；MQ 按（发布者+来源+类型+条件）去重复用兜底。

### 3. 撤单三处（先撤旧账再变更）

- 界面更换管理员（`WorkshopMenu`）
- 管理员死亡（新增 `WorkshopManagerEventHandler`）
- 中心销毁（`ProjectCenterManager.deleteById`）

收起/切任务等 `releaseMaid` 路径不撤单（按主人指示）。标记工具目前不支持更换已有管理员。

### 4. 取消制作单

- 不撤材料单，已购材料留在中心仓库（多余即库存）；仍收回工匠身上带标记的成品。
