# MaidMoreWork：手测反馈与静态审查修复单（2026-09-26）

交给 OpenCode 的独立问题单。用户会手动安排修改；本文件仅分类、定位和提出方案，不表示已经修复。依据是用户的 10 条手测反馈、`20260926-mq-mmw-combined-review.md` 的 MMW 静态结论，以及本次对当前源码的定点复核。手测第 2、9 条属于 MaidQuest，写在该仓库的配套文档中。工作树仍有上一轮未提交实现；先保留现状并核对差异，避免覆盖。不要以 `./gradlew jar` 通过代替游戏内验证。

## 先处理的阻断问题（手测）

### MMW-U01　三种工作描述显示翻译键（用户第 1 条，界面）

- **现象**：采矿、伐木、制作的工作描述显示 `task.maidmorework.logging.desc` 这类原始键。
- **原因**：`lang/zh_cn.json`、`lang/en_us.json` 只有 `task.maidmorework.mining/logging/crafting` 名称，缺少对应 `.desc` 键；TLM 工作列表会请求描述键。与 `projecttype.maidmorework.*.desc` 是两套键。
- **方案**：给三项工作分别补中英文 `task.maidmorework.{mining,logging,crafting}.desc`；核对 TLM 实际生成的键和客户端资源加载。切换三种工作逐一确认名称、描述均为文字。
- **位置**：`src/main/resources/assets/maidmorework/lang/{zh_cn,en_us}.json`，三项 `*Task` 类。

### MMW-U02　工坊 UI 越界、拥挤（用户第 3 条，界面阻断）

- **现象**：按钮和文字超出背景，边距过小。
- **原因**：`WorkshopMenu` 继承的 `GenericContainerMenu` 将宽度算作 170 像素；`WorkshopScreen` 的第三个按钮放在相对 x=174、宽 78，目标按钮最右至 x=202；绑定状态和产品文字也没有限制宽度。屏幕只额外加了 42 高度，却没有统一布局网格；仓库槽位从 x=4 起，仅有约 4 像素边距。
- **方案**：设计工坊专用宽高与分区，统一菜单槽位和屏幕控件的坐标常量；预留真实边距、标题区、绑定区、产品与库存区、54 格仓库和玩家背包区。长文本使用裁切/换行/悬浮提示，不压在槽位上；小窗口和不同 GUI 缩放下检查每个控件的界内矩形。可继续复用容器逻辑，但不要沿用它的 170 像素宽度来摆 250 像素内容。
- **位置**：`crafting/WorkshopMenu.java`、`crafting/WorkshopScreen.java`、FennecLib 的 `GenericContainerMenu.java`。

### MMW-U03　工坊没有工程中心场景悬浮信息和类型（用户第 4 条，功能阻断）

- **现象**：工坊是 `ProjectCenterInstance` 子类，却没有普通中心的场景面板；缺少可显示/识别的工坊工程类型。
- **原因**：`ProjectCenterManager.createWorkshop` 没给实例设置 `projectTypeId`，`ensureWorkshopFromIdentity` 也未恢复类型；`WorkshopBlock.setPlacedBy` 的 `be.setInstanceData` 会把方块实体类型置空。`ProjectCenterInstance.tick` 才广播 `ProjectCenterInfoPayload`，而 `WorkshopInstance.tick` 覆写后没有调用基类广播逻辑。`ProjectTypeRegistry.discover` 只注册伐木和采矿，没有工坊类型。
- **方案**：明确“中心 kind=workshop”和“工程类型=制作”的映射，注册制作工程类型及本地化名称/图标；创建、区块重载、存档反序列化时同步实例与方块实体类型。提取基类信息包发送/通用调度为可复用方法，让工坊 tick 调用，避免直接 `super.tick` 引入不适合工坊的普通扫描逻辑。确认客户端 `ProjectClientHelper.CENTERS` 收到工坊信息并由 `ProjectHudRenderer` 渲染；加载旧工坊存档时补默认类型。
- **位置**：`crafting/WorkshopBlock.java`、`crafting/WorkshopInstance.java`、`project/center/ProjectCenterManager.java`、`ProjectCenterBlockEntity.java`、`ProjectCenterInstance.java`、`lib/projecttype/ProjectTypeRegistry.java`。

### MMW-U04　空九宫格点“录入配方”使服务端崩溃（用户第 5 条，P0）

- **现象**：图书馆九宫格为空时点击录入，服务端退出。
- **原因定位**：`LibraryMenu.validate` 正确返回无效结果，但 `clickMenuButton` 接着调用 `sendPreview`，发包时 `output=ItemStack.EMPTY`；`LibraryPreviewPayload.STREAM_CODEC` 使用 `ItemStack.STREAM_CODEC`，它通常要求非空堆。这是当前源码中共同解释两种崩溃的**高概率路径，缺本次崩溃堆栈，仍须复现核对**。
- **方案**：先核对异常栈是否落在该载荷编码；无效预览改用允许空值的物品栈 codec、`Optional<ItemStack>`，或仅发送有效性/错误键并在客户端清空预览。所有无效输入都返回提示，不能经网络传输非法空堆；服务端 `CONFIRM` 前检查菜单仍有效、方块仍在、权限满足。
- **位置**：`library/LibraryMenu.java`、`library/LibraryPreviewPayload.java`。

### MMW-U05　图书馆槽位背景比物品高 1 像素（用户第 6 条，界面）

- **原因**：`LibraryScreen.extractBackground` 把 18×18 背景画在 `leftPos + slot.x - 1, topPos + slot.y`，只在 X 轴减 1，Y 轴没有减；物品由槽位自身坐标渲染，所以九宫格与玩家背包均错一像素。
- **方案**：槽位背景同时使用 `slot.x - 1` 和 `slot.y - 1`；核对裁切与背景纹理 UV，必要时换图书馆专用贴图，逐行检查九宫格和背包对齐。
- **位置**：`library/LibraryScreen.java`。

### MMW-U06　九宫格仅放木棍使服务端崩溃（用户第 7 条，P0）

- **现象**：摆入木棍即崩溃，不必点击录入。
- **原因定位**：`LibraryMenu.clicked` 对幽灵格每次改动都会 `sendPreview`。孤立木棍不是有效工作台配方，`validate` 返回空产物，随后触发 MMW-U04 同一预览包编码路径；**仍需用本次堆栈证实**。另外检查 `clicked` 的 `SWAP`/快捷键路径，确保只复制样本而不吞物品。
- **方案**：与 U04 一并修空预览传输；针对空格、木棍、无效组合、有效木板/木棍/木镐组合逐项测试，确认服务端存活且玩家物品数量不变。
- **位置**：`library/LibraryMenu.java`、`library/LibraryPreviewPayload.java`。

### MMW-U07　林场无配置 UI，无法直观指定管理员（用户第 8 条，功能阻断）

- **原因**：`ForestBlock.useWithoutItem` 只发聊天状态文字；`ForestRegistration` 未注册菜单/屏幕。虽然标记工具有绑定女仆的分支，但林场本体没有管理员、成员、斧头、仓库或订单的可视配置入口，不能替代用户要求的 UI。
- **方案**：增加林场服务端菜单与客户端屏幕，显示当前管理员姓名、成员、仓库、工具和订单状态，提供绑定/更换/解绑管理员的明确操作；若沿用标记工具，也应在 UI 显示绑定说明和结果。所有更改服务端检查 owner、中心有效、女仆归属唯一性；暂时卸载的管理员显示离线而不清除持久绑定。
- **位置**：`forest/ForestBlock.java`、`forest/ForestRegistration.java`、`forest/ForestInstance.java`、`project/center/ProjectCenterMarkerEventHandler.java`。

### MMW-U08　木板已录入，女仆仍报图书馆缺配方（用户第 10 条，流程阻断）

- **现象**：橡木木板已录入，但管理女仆持续提示缺少其配方；因图书馆崩溃与此问题，木镐逻辑未能继续手测。
- **已见原因**：`CraftingBehavior.tickLearning` 用订单产物 ID 调 `library.recipesFor(product)`；`WorkshopInstance.learnFromLibrary` 遇到已学配方 ID 就 `continue`，连带跳过后来补录的依赖配方；若录入 ID 已在知识表但已失效，学习数为 0 时仍提示“未录入”，提示语也混淆“未录入、配方失效、中心已学、依赖缺失”。`LibraryData.get(level)` 为当前维度 SavedData，跨维度共享承诺亦需核对。**尚未获得手测堆栈/订单产物 ID，不能把具体触发点定死**。
- **方案**：记录/显示当前订单产物 ID、图书馆录入的 output→recipeId、管理女仆维度和中心已学列表；统一规范物品 ID，与真实 `RecipeManager` 对照有效配方及实际产物。学习流程每次遍历依赖，即使上层配方已学；区分未录入、无可达图书馆、过期配方、未学依赖，给准确提示。录入木板、木棍、木镐后重开世界，检查每层知识并继续跑订单。
- **位置**：`library/LibraryData.java`、`library/LibraryMenu.java`、`crafting/CraftingBehavior.java`、`crafting/WorkshopInstance.java`。

## 静态审查：工程中心、制作与物品守恒

以下来自上一轮只读审查，尚未经本次手测验证；每项都应检查当前源码后修复。U03、U08 与若干项相关，但未把它们当成已修复。

### MMW-C01　木镐只订一根原木且可能扣掉木板后卡单（P0）

- **原因**：`WorkshopInstance.collectDemand` 将镐头 3 木板与木棍 2 木板各自展开为一根原木，`refreshReservations`/`pendingMaterialNeeds` 重复抵扣同一根；做出 4 木板后先花 2 块做棍，只剩 2 块。`plan` 又可把同一 2 木板堆同时映射给 3 个镐输入格，`executeCraftStep` 顺序扣料且失败不回滚。
- **方案**：在配方树上聚合同一物料总净需求，再按真实配方批次向上取整；单次制作先按槽位分配总量并验证充足，使用事务/临时拷贝做原子扣料和产物写入，失败不改变库存。以 1 把木镐从空仓库起步验算至少需 2 原木，前后物品守恒。

### MMW-C02　管理员与工匠职责（主人已更正）

- 原审查提出的“管理员不在线就暂停制作”不符合确定的设计，已撤回。工匠按已绑定的中心和订单独立制作，不检查管理员是否在线。
- 管理员接取制作订单、招募工匠，并从中心领取成品交付；只有显式同时绑定工匠身份时才兼任制作。工匠制作出的玩家订单成品留在该订单的中心预留区。
- 本次实现调整了新订单的接取资格、成品移交和自动招募。旧存档中已由工匠接取的 MQ 订单，领取身份不会自动迁给管理员，需另行处理。

### MMW-C03　工作台区块卸载会永久解绑（已修复）

- 未加载的工作台坐标继续持久化；按主人后续决定，中心可基于持久绑定在后台合成，区块重新加载后复核方块有效性。
- 只有区块已加载且方块确认不再是原版工作台时才移除绑定。
- 多张工作台时制作选择当前已加载且有效的一张；场景绑定展示仍读取已登记坐标。

### MMW-C04　配方 ID 不变但产物改变仍消耗材料（已修复）

- 已学和图书馆记录的配方按当前配方输入预览，产物必须与登记物品一致；失效配方不参与选择或缺料展开。
- 每一步制作记录其实际预期产物和数量，包括木板、木棍等中间产物。真实配方匹配后、扣预留前再次核对配方 ID、知识归属、输出物品与本步骤预期数量；不符即等待，预留保持原样。
- 产物数量按当前有效配方重新核算；本修复不把数量变化单独视作知识失效。

### MMW-C05　取消制作单留下材料子单（按设计保留）

- 主人确认多余采购可作为备货。材料单现按中心和材料分批共享，取消单个制作订单不撤销材料采购；已购材料由管理员领取入工坊仓库。旧审查中关于 `sourceId` 和取消身份的原因已过时。

### MMW-C06　取消时管理员卸载导致成品未回收（已修复）

- C02 调整后，工匠只把成品留在中心预留区，管理员才会取出带订单标记的成品。旧审查中“另一工匠携带”的原因已过时。
- 取消时把管理员 UUID 和订单 UUID 记入工坊持久状态；中心全局 tick 在管理员实体再次加载后，仅按订单标记回收其背包中的实物成品并入库。中心区块卸载不影响这项待办。
- 主人补充：工匠或工作台区块卸载后，中心仍按已学配方和真实预留材料在后台合成；管理员加载后再取货交单。女仆被收起、切换任务或死亡不视作普通区块卸载。

### MMW-C07　背包满后成品滞留预留区（已随 C02 调整解决）

- 管理员现在每轮先尝试领取已有成品；插入背包失败时物品退回订单预留区，下轮继续尝试。预留成品抵扣待制作数量，不重复耗料。

### MMW-C08　库存目标调为 0 后旧备货工程继续运行（已修复）

- 目标设 0 时立即结束对应产品的全部备货工程，把其未消耗材料、半成品和已完成品退入工坊仓库；玩家制作订单不受影响。
- 旧存档若遗留目标为 0 的备货工程，全局 tick 会清理；清理前制作、预留和缺料发布入口也会跳过该工程。
- 按主人对 C05 的决定，已发布的材料采购单继续完成并入库备用，不再为已停产的备货工程发布新单。

### MMW-C09　不同材料共享在途计数（已随批次采购调整解决）

- 当前材料来源标签包含中心 UUID、材料候选物品集合和玩家订单/备货类别；在途查询还限定发布者与来源标签。不同材料的在途量不再串账，旧审查原因已过时。

### MMW-C10　管理员转存材料时混入其他订单物资（已修复）

- MQ 领取接口会清除订单标记，物品可合并进管理员已有的同类堆，只返回实际领取数量。工坊因此在领取前后对同一背包逐槽记录物品与数量，只把本次增加的部分转入中心仓库，并以实际领取总量设上限。
- 原有同类物品与其他订单物资保持原位；背包满时领取数为 0，部分领取时只转移成功领取的数量。

## 静态审查：林场、管理员、矿井

### MMW-F01　林场交货失败可能丢失剩余原木（已修复）

- 林场管理员现在每次只从仓库取一堆，按背包实际接收数量结算；未接收的部分立即退回仓库，再处理下一堆。背包满或只容纳一部分时，不会有后续已取出却未处理的堆。
- 背包插入在同一事务中逐槽累计剩余量，避免前一槽部分接收、后一槽又接收完整数量导致复制物品。

### MMW-F02　林场成员委托模式下无单仍砍树（已修复）

- 委托模式下只允许管理员已招募入名单、仍绑定该林场的成员在有效材料单（已认领或执行中）期间砍树；未招募、无单、已完成或已取消时进入待命。
- 砍树行为的开工和持续工作入口都核对实时订单状态，订单结束后释放当前工程分配；管理员轮询时清除失效订单并回收成员。关闭委托模式时保留原有自主行为。

### MMW-F03　装备在手上的借出斧子无法回收（已修复）

- 新借出的斧子带唯一借用标记，回收时先查主副手，再查背包；耐久变化不会影响匹配，也不会按同类斧子误收私人装备。旧存档中无标记的借用记录仅按原完整组件匹配，无法安全辨认已经磨损且与私人斧子同型的旧工具。

### MMW-F04　区块卸载成员被移出名单却仍附着林场（已修复）

- 暂时离线时保留成员、原家与借用记录；无单释放时只解除在线成员。离线成员再加载时按实时订单状态决定继续派工或回收工具、释放工程及中心绑定。

### MMW-F05　标记工具可改动他人中心（已修复）

- 标记绑定中心、绑定女仆/工作台、打开编辑面板、中心命令和工坊菜单均在服务端核对中心主人；非主人只收到拒绝提示。

### MMW-F06　同一女仆可绑定多个种类的中心（已修复）

- 统一扫描所有维度的中心管理员、成员与工匠身份；工坊菜单、标记工具、林场招募及管理绑定共用检查。同中心兼任保留，跨中心需先解除旧归属。

### MMW-F07　补斧后不会给已招募成员重试发斧（已修复）

- 管理员每轮检查已招募且已加载成员的借用记录；未借到斧子的成员会在补货后重试，已有借用记录者不会重复领斧。

### MMW-F08　标记入口不能更换工坊管理员

- **原因**：已有 `managerId` 时 `onEntityInteract` 对工坊一律设置 `craftsmanId`，没有管理员更换操作。
- **方案**：UI/标记工具提供明确的“绑定/更换管理员”和“绑定工匠”动作；换人时同步 MQ 当前管理身份，旧管理员取消权限但中心订单/库存不丢。

### MMW-F09　矿井和普通中心仍可在无管理员时工作

- **原因**：`MineInstance.requestWork/tick` 未查管理员可用；普通 `ProjectCenterInstance.getManagerId` 恒空、setter 无效，标记流程也不能为其配管理员。
- **方案**：实现中心通用的持久管理员字段/绑定与门禁，矿井、普通中心复用；管理员缺席时暂停派工与资源流，已有工程保持可恢复。

### MMW-F10　林场中心失效时仍接单派工（已修复）

- 管理员工作入口和伐木成员的委托派工均核对中心方块已加载且仍为林场；卸载暂停，拆除走既有 `deleteById` 仓库掉落与在线人员/工具清理。

### MMW-F11　砍树入库收走女仆全部原木（已修复）

- 林场砍树与延迟破坏均在掉落进入女仆背包前后按物品组件记录数量，只把这次新增的原木立即送入林场仓库；原有同类木材留在女仆背包。

## 静态审查：图书馆与界面

### MMW-L01　重载后追加同产物第二个配方可能崩溃（已修复）

- `LibraryData` 解码构造时逐条复制配方列表为可变 `ArrayList`，后续追加录入不再修改不可变解码列表。

### MMW-L02　同 ID 产物变更的知识仍可用（已随 C04 修复）

- **原因**：图书馆录入的是产物与配方 ID 的关联，`WorkshopInstance.hasUsableRecipe/chooseRecipe` 只核实配方 ID 仍指向工作台配方，不核实当前输出是否仍等于原登记产物。这与 MMW-C04 是同一缺陷。
- **方案**：按当前 `RecipeManager` 的实际输出重验知识和订单目标，输出改变时使旧知识失效、等待重新录入/学习，绝不先扣料。与 C04 合并实现，不重复计为另一条修复。
- **位置**：`crafting/WorkshopInstance.java`、`library/LibraryData.java`。

### MMW-L03　先学最终产物后补中间配方无法补齐（已随 U08 修复）

- 已学配方仍遍历图书馆依赖，`visited` 阻止循环；后补中间配方可进入学习队列。

### MMW-L04　工坊界面会向持久仓库写入空堆（存档风险，已修复）

- 界面以运行时空格保留槽位映射，中心编码时仅写入非空物品堆；重载后回到压缩表示，不把空堆写入存档。

### MMW-L05　工作台卸载解绑（已随 C03 修复）

- **原因**：`WorkshopInstance.hasValidTable` 将“区块未加载”和“方块已不是工作台”都交给 `removeIf`，把临时卸载写成永久解绑。这与 MMW-C03 是同一缺陷。
- **方案**：保留未加载位置，待区块加载再验证；仅在已加载且确认方块失效时移除。按主人后续决定，已登记工作台卸载期间允许中心后台合成。与 C03 合并实现。
- **位置**：`crafting/WorkshopInstance.java`。

### MMW-L06　工坊菜单越权绑定与跨中心绑定（已随 F05/F06 修复）

- 工坊打开和按钮操作均检查中心主人及距离，人员绑定共用跨中心归属检查。

### MMW-L07　管理员无法在工坊 UI 兼任工匠（已随 C02 修复）

- **原因**：`WorkshopMenu.bindMaid` 绑定管理员会清掉同一人的工匠字段，绑定工匠又拒绝现任管理员；与 `WorkshopInstance` 允许兼任的字段设计不一致。
- **方案**：允许同一女仆在**同一中心**同时占有两角色，界面分别显示两种职责；跨中心仍按 F06 禁止。

### MMW-L08　仓库超过 54 堆后的物品不可见不可取（已修复）

- 工坊及林场仓库均按 54 格分页，服务器按钮翻页后同一菜单同步槽位；仓库末页始终可继续存入，已有后续物品可查看和取出。
