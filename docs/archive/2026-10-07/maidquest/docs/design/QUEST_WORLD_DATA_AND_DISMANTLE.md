# 委托数据全局化与安全拆除

> 记录日期：2026-09-27  
> 状态：按作者确认的方案实施；旧存档数据不迁移。  
> 范围：MaidQuest（MQ）；公共仓库属于其他模组的业务。
> 2026-09-28 补充：加载边界的跨模组修订草案见 [MQ × MMW 加载边界与生产推进规则](../../../docs/design/LOADING_AND_SIMULATION.md)。以下已实施的 MQ 数据归属规则保持有效。

## 1. 最终决策

| 主题 | 规则 |
|---|---|
| 数据 | 每维度 `QuestBoardData` 是订单、每单托管、板坐标和找回中心的权威存储。方块实体只作为物理交互入口。 |
| 板与订单 | 订单保留所属板坐标；界面只展示当前板的订单。 |
| 同步 | 打开界面时请求快照；数据改变后向该板的观看者推送快照。 |
| 取消与拆除 | 托管货立即尝试塞进交付女仆背包。女仆未加载或背包装不下的部分进入持久找回中心。无待取回队列、女仆寻路或传送步骤。 |
| 拆除 | 任意玩家可从界面点拆除。同步取消订单、处理货物并移除板，只通知发起者。玩家直接挖掘被拦截。 |
| 完成单 | 尚未被发布者领取的托管货，在取消或拆除时仍归交付女仆。 |
| 女仆收起 | 订单退回待接取，托管货进入找回中心，因为 TLM 已经先把女仆序列化为物品。 |
| 女仆死亡 | 当前托管货和该女仆名下找回中心条目都交给公开处置回调。MQ 默认掉落在在线主人的位置；主人离线或找不到时掉落在女仆死亡位置。 |
| 通用仓库 | 废弃板级 54 格通用仓库及其菜单、界面和网络载荷；交付型使用每单专属托管。 |
| 兼容性 | 开发期不迁移旧存档数据。 |

## 2. 数据与归属

`QuestBoardData` 使用新的 SavedData 标识 `maidquest:quest_world`。每个维度分别保存：

- 板坐标、完整订单列表；
- 按订单 ID 分隔的托管物品和交付时记录的主人 UUID；
- 找回中心条目：女仆 UUID、可选主人 UUID、物品列表。

托管货的交付者由订单当前接取女仆确定。订单退回待接取时，先把托管货取出并归还，再清除接取关系，避免货物转给下一位接单者。若出现有托管货但无接取女仆的异常记录，货物在原板坐标掉落。

找回中心无超时。女仆加载时及服务器低频扫描时，MQ 尝试把条目物品插入女仆可用背包；只删除已经插入的数量，剩余部分继续保存。女仆可能跨维度，因此派发时搜索全部维度。找回中心条目记录主人 UUID，使女仆随后死亡时仍可把货物交给正确的处置目标。

## 3. 生命周期

1. 发布、认领、执行、部分交付、完成和发布者领取沿用现有语义。部分交付进入该订单的专属托管。
2. 发布者取消、批量取消、女仆主动放弃：订单停止或重开，托管货立即还给女仆；找不到女仆或背包满时进入找回中心。批量取消直接读 SavedData，因此板所在区块可以卸载。
3. 女仆被收起：通过 TLM 的 `MaidAndItemTransformEvent.ToItem` 处理；订单重开，托管货进入找回中心。区块卸载不视为收起。
4. 女仆死亡：订单重开，当前托管货及找回中心货物交给死亡物品处置接口。已完成但尚有托管货的订单也按此规则重开。
5. 拆板：同步阻止新发布和认领，逐单取消并处理托管货，移除全局订单和板坐标，随后移除方块并掉出委托板物品。异常移除方块时也执行清理。

## 4. 客户端与板交互

- `QuestBoardQueryPayload`：客户端请求当前板；服务端验证距离和方块实体。
- `QuestBoardDataPayload`：服务端返回该板订单、托管输出标记、板是否存在。
- `QuestBoardClosePayload`：关闭界面时结束观看会话；断线和停服也清理会话。
- `QuestBoardScreen` 读取 `QuestBoardClientState`，发布、取消、领取后等待服务端推送。
- 底部提供「拆除」按钮，移除旧「交付仓库」按钮。

普通玩家挖掘委托板时，`BreakBlockEvent` 取消破坏并提示从界面拆除。高爆炸抗性和禁止活塞推动减少绕过。命令或其他模组移除方块时，方块实体的移除回调负责处理订单和托管货。

## 5. 对外 API 与 MMW

原有 `QuestApi` 方法签名维持。新增 `QuestItemDisposalRegistry.register(QuestItemDisposal)`，供其他模组注册死亡物品处理器。处理器得到死亡维度、女仆死亡坐标、女仆 UUID、可选主人 UUID 和待处置物品；返回尚未处理的物品。MQ 会按默认规则掉落返回的剩余物品。其他模组可以在此实现自己的公共仓库逻辑，MQ 不直接管理公共仓库。

MMW 调用 `cancelMaterialsByPublisher` 时，已卸载委托板上的材料单也会被取消。原有 `requestMaterial`、`materialOrdersFor`、`claimOutput`、`cancel`、`boardsNear` 等入口不变。

## 6. 代码审查与编译验收

开发完成后仅核对代码中是否有逻辑漏洞、是否符合上述方案，并运行 `gradlew jar` 确认能编译。按本项目开发规则，不运行游戏测试、测试任务或其他自动化测试。游戏内功能点由作者另行验收，旧存档迁移不在本次范围。

## 7. 区块卸载与订单推进的边界（2026-09-28 评审补充）

- 板坐标和订单记录持久存在，不代表委托板区块已加载。现有 `boardsNear` 只列已加载的板；发布、认领、交货和领取还需板方块实体与女仆实际在场。卸载期间保持订单和托管原状，恢复时重新核验。
- 按发布者批量撤销材料单可直接操作 `QuestBoardData`，即使板区块卸载也能撤单；退还给暂时未加载女仆的货物应进入持久找回中心，不能掉进未加载的区块。
- 女仆暂时查不到时保留认领身份；收起、死亡、主动放弃由相应事件改变订单状态。重载后的附件与 `QuestBoardData` 不一致时，以订单数据核对认领关系，并避免重复交货。
- 订单状态变化、每单托管和跨模组中心入库是三个阶段；任何一步失败都不能同时声称货物仍在托管且已经入库。后续与 MMW 衔接时，需要稳定操作 ID、幂等重试和明确的等待原因。
