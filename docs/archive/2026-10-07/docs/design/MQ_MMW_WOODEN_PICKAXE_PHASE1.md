# MaidQuest × MaidMoreWork：木镐订单循环第一阶段计划

> 状态：历史第一阶段计划；部分已实现，原单人工作站、女仆持有知识和木匠本人发材料单等规则已被后续工程中心设计取代。以下步骤保留为设计演变记录，不再作为当前实现规格。
> 讨论日期：2026-09-25。
> 上位设计：[订单驱动生产链](MAIDQUEST_MMW_ORDER_CHAIN.md)。本文件只规定第一阶段；矿场合约、公共仓库和货币结算留待后续。
> 当前加载边界草案：[MQ × MMW 加载边界与生产推进规则](LOADING_AND_SIMULATION.md)。

## 目标与验收流程

1. 玩家在 MQ 委托板发布指定数量的木镐订单。只有工种为“制作”、且绑定了有效工匠工作站和原版工作台的女仆能接单。
2. 木匠先检查自己携带的材料和工作站库存；缺原木时，由**木匠本人**发布原木订单，并保留正在等待材料的木镐订单。重复检查不能重复发布同一缺口。
3. 工种为 MMW“伐木”的女仆接原木订单，继续使用 MMW 的伐木行为产出原木，带到委托板按订单交付。已在背包中的合格原木可以优先交付；背包满时允许部分交付。
4. 原木订单交齐即完成。木匠到委托板领取属于该单的原木，实际运回工作站，按游戏配方制作木板、木棍和木镐；剩余材料与中间产物保存在工作站。木镐按根订单交到委托板，由发布订单的玩家专属领取。
5. 木匠**接到首张木镐订单时**记住木镐有需求；在当前订单结束后，才开始自主备货。工作站常备目标默认 5 把，可在工作站界面调整或设为 0。达到目标后待命；再次接到木镐订单时先用未预留现货，不足部分才制作，随后补回库存缺口。

第一阶段要有真实的物品移动和配方消耗，但不引入报价、数字余额或买卖结算。“知道有人买”是备货动机，尚不产生收入。

## MQ：订单、任务板和调度

- 保留现有第三方 `IQuestType` 等扩展 API；删除 MQ 自带的测试用伐木委托类型、伐木执行器、注册入口及相关测试说明。第一阶段使用新世界验证，**不迁移旧 MQ 伐木委托存档**。MQ 单独运行仍应能加载，木镐选项仅在 MMW 适配注册后出现。
- 增加物品订单模型及服务端接口：订单 ID、发布者与收货者的稳定 UUID、父订单 ID、物品条件与数量、认领者、已交数量、状态及所属委托板。木镐根单要求精确物品；原木子单接受能够按当前配方做成木板的原木。父子关系用于缺料去重和恢复生产，**不表示取消时连带撤销或退回已经完成的子单**。
- 委托板按订单 ID 单独持久化托管物品，记录每批交付者。交付不得超过剩余需求；领取需验证收货者、物品实际存在且尚未领过。玩家领取自己的木镐，木匠领取自己原木单的交付物。现有共享仓库不承载这些新订单的物品。
- 接单前强制检查工种、工作站与可制作物品；权重仅用于合格女仆之间选取。木镐根单等待原木时保持木匠的认领关系并暂停执行，原木到货后恢复。同一女仆每次只执行一个实际动作。
- 用 TLM 的 `MaidContainerGuiEvent.Init` 在女仆面板加入持久化的“委托模式”按钮，初始开启。开启时优先接合格订单；关闭时优先自主工作或备货，无自主目标时仍可接单。已认领订单的交付优先于这两种倾向，避免 MQ 与 MMW 同时导航。

## MMW：生产与库存

- 注册“制作”TLM 工种、新的工匠工作站方块及其库存和界面。工作站界面绑定附近一名制作女仆和附近一张原版工作台，一站一名女仆；绑定失效时暂停制作，物品继续留在仓库。
- 制作女仆的“已知产品”和各产品常备目标持久化在女仆身上；材料和成品持久化在工作站。女仆换站时知识跟随女仆，原站物品不会瞬移。工作站界面显示并调整已知产品目标，先只开放木镐。
- 木镐阶段使用游戏配方校验原木→木板、木板→木棍、木板与木棍→木镐的输入输出；实际扣除物品后才生成成品，保留余料，不按设计示例硬编码“需要两根原木”。工作站缺料时按现货、已托管和在途数量计算缺口；自主备货同样有界且不能重复发原木单。
- MMW 在 MQ 存在时注册制作与原木供货的资格和行为适配；MMW 单独运行时原有伐木、采矿工作仍可使用。MQ 的订单执行与 MMW 的生产行为共用同一女仆调度，不并发抢夺导航。

## 订单归属与中断规则

- 玩家只能取消自己发布、尚未领取的木镐根单；木匠或系统才能取消木匠发布的原木单。玩家取消木镐单**不影响**原木单：已领走的木头属于木匠的材料。已制作但尚未被玩家领取的木镐由木匠实际收回工作站；未使用的材料也留在工作站。木匠接单时已记住木镐，取消后仍可按目标备货。
- 原木单尚未完成时由发布者取消，委托板按交付记录为每位交付者保留退货领取权；未交的原木仍在伐木女仆背包。原木单完成并由木匠领取后，不再追溯原木或撤销已完成的供货。
- 背包或工作站放不下、工作台或委托板暂时不可用时停止物品转移并保持可恢复状态；区块卸载不当作方块被拆。真实拆除时保全实体库存，并让未完成订单进入可见的阻塞或重新认领状态。所有转移在服务端核对容量与数量，避免重复交付、领取或凭空生成物品。

## 验证与实施顺序

1. 先实现 MQ 的物品订单、按单托管、专属领取、资格筛选和取消规则；移除测试用 MQ 伐木逻辑。
2. 实现 MMW 工匠工作站、绑定界面、制作工种、真实木镐配方和女仆记忆；接入 MMW 伐木供货与 TLM 委托模式按钮。
3. 用针对性测试覆盖部分交付、重复提交与领取、原木单独立性、根单取消、库存缺口与备货上限、重载恢复。分别构建 MQ、MMW，并在联合游戏环境验证本文件开头的完整流程，以及背包满、无树、工作站失效、委托板拆除等场景。

实施时保留 MMW 当前已有的未提交改动；本计划本身不代表代码已经实现。
