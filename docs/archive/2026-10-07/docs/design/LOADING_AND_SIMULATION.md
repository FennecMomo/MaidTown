# MQ × MMW：加载边界与生产推进规则

> 修订日期：2026-09-28  
> 状态：供重新讨论的修订草案；本文件的 A/B/C 分层是审查框架，工坊是否允许卸载制作尚未拍板。  
> 范围：MaidQuest 的委托、托管与找回；MaidMoreWork 的工程中心、工坊、林场、矿井和图书馆。MaidTown 尚未接入。
> 后续讨论见 [世界模拟重设计笔记](WORLD_SIMULATION_DISCUSSION.md)。本文的分层和限制是助手建议，尚未作为玩家城镇的最终规则确认。
> 后续决定已替代本文部分假设：居民卸载前转为后台实例继续履职；工坊归管理员私有，普通管理员换岗是测试逻辑；产业仓库无限容量且玩家只能查看，公共仓库容量有限且允许玩家存取；死亡与拆除按讨论笔记中的产权和运输规则处理。下文保留为早期审查草案，不据其旧假设直接实施。

## 1. 四种容易混淆的状态

1. **服务器运行，区块加载**：可以检查方块、方块实体及该区块中的实体，但仍要分别验证目标存在和权限。
2. **服务器运行，区块卸载**：世界存档中的中心与订单数据仍可读写；区块内的方块、库存和实体状态未知。`getEntity(uuid) == null` 只表示当前未找到实体。
3. **维度卸载，服务器仍运行**：该维度不再 tick，其 SavedData 待重新加载；其他维度继续正常运行。不能把一个维度卸载当成整个服务器关闭。
4. **服务器关闭**：所有维度都不推进订单、工作或倒计时。重启后恢复持久状态，不用现实时间补产出。
5. **游戏内跳时**：未来 MaidTown 的睡眠批量结算是一项显式规则，不等于区块卸载。它只结算已定义的需求与社交数值，不补做采集、制作或物流。

“离线”在本文只表示实体或区块未加载；它不表示维度卸载或服务器关闭。所有持续时间以实际执行的服务器 tick 计，不按现实经过时间或跳过的游戏日时间追赶。

## 2. 数据权威与动作边界

| 数据或动作 | 权威位置 | 卸载期间规则 |
|---|---|---|
| MQ 订单、状态、板坐标、每单托管、找回条目 | 每维度 `QuestBoardData` | 可做纯数据查询、取消、标记待领取；不依赖板方块实体常驻。 |
| MMW 中心身份、绑定、仓库、工程、预留、已学配方 | 每维度 `ProjectCenterData` | 可维护持久账本、计算缺口、记录等待；不能凭“中心仍有记录”推断物理方块仍存在。 |
| 图书馆配方记录 | `LibraryData` | 已录知识可查询；学习动作仍须女仆与可达图书馆实际在场。 |
| 女仆背包、位置、导航、工作状态 | 女仆实体及其持久附件 | 实体未加载时不取放背包、不移动、不把“未找到”判为死亡或辞职。 |
| 委托板、工作台、树、矿石、中心方块 | 已加载世界 | 只在目标区块加载后核验或修改。不得为了轮询而隐式加载区块。 |

所有跨仓库、托管或女仆背包的物品移动，都由服务端执行一次可验证的转移：先确认来源实物、目标容量和操作身份，再更新双方及订单进度。失败保留原状或把剩余物明确留在持久找回区，不能靠“下一次 tick 应该会补上”掩盖丢失。

## 3. 统一推进分层

| 层 | 允许的工作 | 前置条件 |
|---|---|---|
| A：纯账本 | 订单状态、缺口与预留核算、超时提示、等待原因、幂等清理 | 服务器运行；相关 SavedData 已恢复。不得凭未知世界状态取消绑定或删除成员。 |
| B：抽象加工 | 用已预留的真实物品按有效配方生成中心库存中的产物 | 仅对明确允许抽象加工的工种开放；有持久作业、工时预算、有效人员资格和工作设施凭证；实际扣料与产物入库原子提交。是否允许工作台/工匠卸载时继续，本轮待定。 |
| C：现场行动 | 寻路、砍树、挖矿、学习、招聘/交工具、从女仆背包取放、委托板交付或领取、世界掉落 | 必需实体与目标方块均已加载且可交互；失败进入等待，加载后重新核验。 |

草案建议中心全局 tick 只保证 A 层能运行，B 层另行定义准入，C 层必须验证现场。采矿和伐木改变世界方块，归 C 层；若要允许离线产出木头或矿石，就需要独立设计资源耗尽、地形同步和可见性规则。MQ 的发布、接单、交货和领取涉及板或女仆，归 C 层；已存在订单的取消、托管退还登记可按 A 层推进。

## 4. 抽象加工的最低契约

若最终决定保留工坊的卸载制作，应先把它当成明确的模拟功能，而不是“找不到工匠就调用一次合成”。每笔作业至少持久化：工程/订单 ID、中心 ID、产品与配方 ID、工匠绑定及有效资格、设施位置及最后核验状态、输入预留、已完成数量、剩余工时和下一步的唯一序号。执行时遵守：

1. 接单或开工时在已加载场景中验证工匠、工作台、配方与权限。卸载只把状态改为“待观察”；死亡、收起、换工种、解绑、工作台确认拆除是停止事件。
2. 服务器实际执行一次 tick 才给作业累计有限工时，正常加载和卸载只能走**同一条**工时与合成路径；一次工时不能被实体行为和中心后台重复消费。停止或重启期间不按时间差补算。
3. 每次产出前重新验证当前配方和预留的真实输入；一次性扣除输入、加入真实输出并记录工程进度。产物留中心预留区，女仆或板未加载时不假装已经领取或交付。
4. 若设施所在区块未加载，服务器只能确认“曾登记”，不能确认它此刻仍是工作台。继续生产必须由设计明确接受这段延迟校验窗口；加载后若发现设施已失效，从该时点停止，不凭空回滚已经交付的产物。
5. 世界变化、配方数据包变化或工匠资格变化无法安全判断时暂停该作业，并提供可见的等待原因。保存与重载后不得重复结算上次已完成的一步。

**当前实现不满足这份最低契约。** `WorkshopInstance.tickBackgroundCraft` 按 10 tick 尝试制作，凭持久的 `craftsmanAvailable` 和未加载的登记工作台继续执行；没有统一的工时/执行者租约。此处需要先定产品规则，再改实现。

## 5. 生命周期与恢复

| 事件 | 应执行的处理 |
|---|---|
| 区块或实体普通卸载 | 保留中心、订单、成员、绑定、预留、托管；暂停 C 层动作。只记录“待复核”，不清除身份。 |
| 重新加载 | 核对同一维度中的方块身份、女仆绑定及订单版本；恢复可继续的作业。发现真实拆除或换工种后走明确的清理流程。 |
| 管理员/工匠死亡、被收起、主动换岗 | 由事件写入持久状态并释放或转交岗位；不能靠每 tick `getEntity` 结果猜测。身上实物按死亡/收起规则处置。 |
| 中心或委托板真实拆除 | 只在确认方块已被移除时执行一次清理；先安全处置托管、预留、仓库和工具，再删除权威记录。重复回调不重复掉落。 |
| 服务器停止与重启 | 保存状态；重启后按记录恢复并核验；不补做停机期间的工作。 |
| 单个维度卸载与重载 | 只清理该维度的运行时索引；其他维度继续运行。重载后从该维度 SavedData 恢复，不按未运行时间补工作。 |
| 睡觉跳时 | MaidTown 将来按日节律规则结算需求/社交；不触发 MMW 资源产出与 MQ 交货。 |

处理跨 MQ/MMW 的取消、发布、领取时，保存稳定操作 ID 和阶段；每一步可重试且幂等。MQ 订单的“已交托管”与 MMW 中心的“已入库”是两个不同事实，只有实物转移成功后才能推进后者。后续已确认工坊归管理员私有，不设计普通管理员换岗交接；管理员死亡后按充公规则处置。中心持久保存库存是数据存放方式，不代表物品脱离管理员产权。

## 6. 当前模块的应用

- **委托板**：SavedData 能让已有订单在板区块卸载时保持可查、可取消；新发布、认领、实际交付和领取等待板与女仆加载。找回中心保管退货，女仆再次加载后尝试返还。
- **工坊**：缺口、库存目标、预留属于 A 层；合成是否开放 B 层待定；管理员去图书馆、发布/领取材料单、取成品交板属于 C 层。取消单不得吞掉已投入作业的材料或已完成的半成品。
- **林场与矿井**：订单需求和成员名单可持久保留；招募、借还工具、砍树、挖矿、扫描真实方块、交货都需已加载现场。成员暂时找不到时保留岗位并标记待复核。
- **图书馆**：知识与馆坐标分开保存；馆卸载时保留坐标与记录，待加载后验证方块；不能因为读不到方块就删配方。

## 7. 验收场景

1. 玩家远离中心、工作台、女仆、委托板，再返回：订单 ID、成员、库存与预留不丢；现场动作没有在未知世界发生。
2. 仅卸载中心区块，女仆与板仍加载；仅卸载女仆，中心与板仍加载；分别检查每个动作的前置条件和等待原因。
3. 卸载后重启服务器，再加载各区块：不按停机时间补产物、重复发布采购单、重复领货或重复退货。
4. 女仆死亡/收起/换工种、工作台或中心真实拆除与普通卸载逐一测试；失效清理只发生一次。
5. 同一制作工程在加载/卸载交界切换：若允许抽象加工，总工时和实际材料消耗只计一次，成品数量一致。
