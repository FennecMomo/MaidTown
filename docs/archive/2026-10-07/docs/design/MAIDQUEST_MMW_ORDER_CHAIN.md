## 1. 设计缘起与当前范围

MMW 独立使用时遵循 TLM 的工作逻辑：女仆被分配伐木、采矿等工种后，持续尝试工作。原先的 MaidTown 设想还包括居民自身的需求、能力、时间和经济状况；这些因素会产生工作选择与委托的动机。MQ 从 MaidTown 抽出后，虽然保留了任务板和接单、执行、交付过程，却失去了产生请求的需求层。单纯让已经会持续工作的女仆再接一张“砍树”委托，并不能构成新的玩法。

当前讨论的解决路径：**先由玩家发出有明确产物的根订单，缺料时优先查看既有物资和公共仓库，再派生确实无法由现货满足的子订单；管理女仆也可以根据有限库存目标持续备货和招募。** MMW 提供生产能力和现场物资，MQ 连接需求、劳动合约、物流与基础货币账，使 MQ+MMW 形成生产和买卖循环；MaidTown 将来可继续扩展居民需求和私人产权。

本阶段的“闭环”包括 **订单生成 → 采购／制作／施工 → 逐级交付**，以及 **矿场招募 → 矿工交货累计工分 → 工资结算 → 矿场售矿 → 公共仓库交易**。MQ 要有可用的个人数字余额、公共仓库账户与固定报价入口；已确定物品按“原价”计工分、仓库不随库存调价，以及制作加价和招募工资的倍率；基础原价的具体数值仍需讨论。

## 2. 已确认的设计原则

1. **职责**：MQ 负责订单关系、接取／发派、进度、劳动合约、交付托管及数字货币／交易框架；MMW 负责工种、工作站／矿井绑定、工程施工和矿井仓库。MaidTown 以后可提供居民需求、进一步的产权与价值规则。
2. **委托倾向开关**：在 TLM 女仆面板增加“委托模式”按钮，保留女仆已选的 MMW 工种。开启时倾向前往委托板接适合自身工种的任务，关闭时倾向自主工作；这是**优先倾向，不是绝对禁止另一类行为**。无适合订单时可以做有上限的备货，达到库存目标后待命。具体权重、行为互斥和按钮接入方式待定。
3. **工种与能力**：计划给 MMW 新增“制作”和“管理”；制作女仆绑定的工作台或熔炉决定能处理的配方，管理女仆绑定矿井。伐木和采矿女仆仍使用 MMW 相应工种。管理者不只是搬运工，还代行矿场经营者职责：招募矿工、提供工具、响应缺口、分配矿场产物及处理矿场交易。
4. **订单可以派生订单**：等待材料的上游订单不能丢失；工作人员可在上游订单挂起期间处理使其恢复的下游订单。示例中 A 挂起铁镐单后仍可制作木镐、石镐。女仆为库存缓冲而适度超量订货、管理者在无矿石订单时维持 3～5 份有工分目标的采矿合约，均属于有上限的内部需求，不能无限自我增发。
5. **采矿招募与工分工资**：每条招募是**一份固定工分量、固定数字报酬**的劳动合约；“五条”不是必须同时招满五名矿工。报酬为 `R` 时目标工分为 `10R`；矿工向矿场**实际交付**的物品按其固定“原价”记工分。挖掘不同方块可能产出不同价值的物品；填洞、照明等无产物工序不计工分。矿工做满工分后退出矿井并立即取得报酬，管理女仆以个人余额支付；不足时其个人余额可为负，矿工仍足额收到钱。
6. **矿场物资归属**：矿场承担工具成本，矿工免费领取工具干活；产出的矿物属于矿场，由管理女仆负责分配、交付物品订单或出售。矿工缺工具时在矿井发请求、等待补给，不自行退出；工作背包满时回矿井清货，不去任务板交部分矿物。矿工个人物品入矿前在矿井单独暂存，不与矿场产物混放。
7. **中断与交付分工**：正常采矿合约做满工分才让矿工离矿、结算工资；死亡则中断该合约，未完成工分清零、本单不支付。任务板的**部分物品交付与暂时代管**仍适用于伐木、制作、矿场管理等物品订单，但矿工不再为了交矿石订单离开工程；矿场的物品订单由管理女仆履行。
8. **物品固定原价**：沿用“基础产物手动定价、合成产物按配方计算”的方向，同种物品的原价**不随公共仓库库存变化**；矿工交货直接按原价算工分，不按仓库某次实际成交价追涨跌。基础产物的价目表、特殊产物以及配方分歧尚待确定。
9. **制作订单人工费**：按用于制作该批成品的材料**固定贩售价**合计 `M` 计算，成品基础售价为 `1.2M`，其中制作人工费为 `0.2M`；不是在材料费之外再额外收 `1.2M` 人工费。超量采购但未消耗的材料仍是库存，不计入这批成品的材料费。具体材料价口径与付款方见 §7。
10. **基础货币与公共仓库**：每名女仆生成时获得 100 的初始数字余额。公共仓库是**物资中转站**：缺材料时先检索其可用库存，能获取的现货先用于履行需求，剩余缺口才下新单；矿场管理者在资金不足以支付工资或购置工具时，将可出售的矿场产物卖给公共仓库换钱。公共仓库与矿井仓库、任务板托管仓库相互独立；按固定报价收货时立即付款、卖货时向购买者收款，不做库存驱动的涨跌，可以在额度内短期透支。收购与出售是否同价、透支额度尚未决定。
11. **MQ 内现有伐木委托是测试占位**：它不是今后衔接 MMW 的正式伐木工作实现，后续要删除或迁移；处理旧存档的办法尚未决定。

## 3. 铁镐订单的目标流程（讨论原型）

以下记录主人提出的 24 步场景，保留角色、材料数量和动作顺序；“铁矿石”等实际物品名需在实现时依据配方与掉落校验，见 §7。

| 步骤 | 预期事件 |
|---|---|
| 1 | 玩家在委托板下达“一把铁镐”订单。 |
| 2 | 制作女仆 A 绑定工作台，接取铁镐订单并返回工作台。 |
| 3 | A 发现缺三个铁锭和一个原木，在委托板发布材料订单，暂时挂起铁镐任务。 |
| 4 | 制作女仆 B 绑定熔炉，接取“三个铁锭”订单并回到熔炉。 |
| 5 | B 发现缺三份铁矿原料和一个煤，发布相应材料订单。 |
| 6 | 管理女仆 C 绑定矿井，接取“三份铁矿原料”和“一个煤”的供货需求，并发布五份固定工作量的采矿招募。 |
| 7 | 采矿女仆 D 接取一份采矿招募，前往矿井。 |
| 8 | D 遇到石头但没有合适工具，向矿井提出缺工具请求；C 收到后发布“一把木镐”订单。 |
| 9 | A 因铁镐订单尚在等待材料，接取木镐订单，并发布“两个原木”材料订单。 |
| 10 | 伐木女仆 E 接取原木需求，在伐木工程中心附近砍树；当前共有“一原木”和“两原木”两笔订单。 |
| 11 | E 交付“两原木”后，A 领取这批材料制作木镐。 |
| 12 | A 交付木镐；C 将其送到矿井，D 取得木镐后继续采矿。 |
| 13 | E 交付余下的“一原木”订单。 |
| 14 | D 挖到圆石和煤并存入矿井；C 领取煤并交付“一个煤”订单。 |
| 15 | B 领取已交付的煤。 |
| 16 | D 遇到铁矿但现有工具不够，矿井请求更合适的镐；C 发布“一把石镐”订单。 |
| 17 | A 接取石镐订单，发现缺“三块圆石”，发布材料订单。 |
| 18 | C 从矿井仓库取出圆石并交付“三块圆石”订单。 |
| 19 | A 领取圆石制作石镐。 |
| 20 | A 交付石镐；C 将其送到矿井，D 获得石镐并继续挖铁矿。 |
| 21 | D 挖出足够的铁矿原料后，C 从矿井取得并交付“三份铁矿原料”订单。 |
| 22 | B 领取原料，在熔炉制作三个铁锭。 |
| 23 | B 交付“三个铁锭”；A 领取后制作铁镐。 |
| 24 | A 交付“一把铁镐”，玩家的根订单完成。 |

依赖可以理解为从铁镐根订单向下展开的**订单图**：配方产生材料需求（铁锭、燃料、木材），现场阻塞产生应急工具需求（木镐、石镐），矿井管理产生劳动力需求（五份交货价值工分合约）。矿井招募完成只代表完成了对应交货工分量，**不保证矿井一定有铁矿**；原料订单由 C 实际交出物品才完成。

**该示例省略了工资账，并不表示 D 无偿挖矿。** C 发布的每份采矿合约需标定报酬 `R` 和目标工分 `10R`。D 把矿物交到矿井时按其价值积累工分，由 C 将矿场物资交付给 B 或送往公共仓库；D 达标后才退出矿井、领取报酬。B 和 A 的制作单也需计入所消耗材料的价值以及制作人工费。已有物品库存、有限备货与其他女仆的购买，可能改变各步实际发生的先后顺序。

## 4. 使流程成立所需的系统约束（方案草案，尚非全部拍板）

### 4.1 订单关系、挂起和排程

- 物品订单至少需要：唯一 ID、要求的物品及数量、发布者／收货方、父订单／根订单、完成状态与实际交付量；制作单还要记录材料成本与人工费的结算依据。采矿工作合约还需要工作地点、`目标工分 = 报酬 × 10` 和已确认的交货工分。
- “等待材料”是可恢复的状态，不等于放弃订单；A 可持有待恢复的铁镐单，同时执行木镐或石镐单。C 作为管理者还会同时观察矿井、多笔供货与招募。女仆每 tick 应只执行一个实际工作，但可以管理多个等待中的订单／关系。
- 生成子订单前依次核对已持有／已托管且可动用的材料、公共仓库的可用现货与在途／已预留数量；能从公共仓库获得的材料先走购买与领取，剩余缺口再查未完成订单并发布新子单。同一缺口重复检查不能无限增发订单；应防止依赖环和所有工人都占着父订单等待子订单的死锁。
- 订单模式需要对工种、绑定工作站、可处理配方及目标矿井做**资格筛选**；匹配度加权只决定合格者中选谁，不应让任何路过的女仆都接“制作铁镐”。
- 生产缓冲按目标库存减去现货、已预留量和在途订单计算缺口；例如需要五块木板时主动订十个原木，超出的物品必须有明确的库存去处。C 常驻招募 3～5 份采矿合约也应受矿场库存与需求边界约束，做完一份才按当前缺口判断是否补发。

### 4.2 任务板作为有归属的物流节点

- 按**订单 ID**记托管数量和物品：E 的两份原木属于木镐材料单，一份原木属于铁镐材料单；B 的煤或铁锭同理。物理仓库可以共用，但领取者只能消费分配给其上游订单的份额。
- C 从矿井仓库取货 → 运到任务板 → 对应订单收到货；A/B 从任务板领取已分配的材料 → 运到绑定工作站。木镐、石镐反向经任务板交付，由 C 送入对应矿井，D 才能取得工具；物资不凭订单完成自动瞬移。
- 一次交付至多接受本订单尚缺的数量。部分交付、领取、取消、任务板被拆和背包／仓库已满时的去向必须明确，避免同一份圆石或煤被两张订单重复计算。
- **矿井仓库**收施工产物、供矿工领工具和由 C 分配；**任务板托管仓库**保存具体物品订单的交付物；**公共仓库**接收可交易的剩余产物、为缺料订单提供既有物资。公共仓库有货时需先锁定／购买对应份额，防止两个订单同时把同一批现货当成自己的材料。再加上女仆在矿井的个人物品暂存，四者在物理存取与归属上均不能混为一个容器。

### 4.3 矿井交货与固定工分合约

- 矿工持有采矿合约入矿时，先把个人物品放进**按女仆隔离的暂存区**，避免被矿井清货逻辑当作矿场物资；矿井免费提供所需工具。工作背包满则回矿井把施工产物入库，继续同一合约；缺工具则留在矿井等待 C 补给。
- **只按实际交到矿井的物品固定原价记工分**，不能单凭挖掘动作、发现目标或背包里有物品记分；入矿前的个人物品、矿井发放的工具、重复取出再存入的库存也不能冒充新产物。填洞、照明、放控制方块、寻路、等待工具、取货等无产物工序不计工分。不同方块产出的物品种类与数量影响工分，同种物品不会因仓库库存变化而改变工分。
- 达成目标工分后，在安全工序边界停止、清理施工产物、归还矿井工具、取回暂存的个人物品，释放工程席位并退出矿井；MQ 验收一次并发放一次工资。死亡为特殊中断：本单进度清零且不付本单工资，工程与个人暂存物的后续处理见 §7。
- 工具缺口需要包含矿井 ID、受阻目标、所需工具能力／等级和缺口数量的结构化信号；C 在仓库有货或相同订单正在制作时不应重复下单。矿井缺资源、材料无法取得或矿层确实没有目标矿石时应能报告阻塞，不能无限招募、无限循环。

### 4.4 数字余额、工资与公共仓库

- MQ 保存女仆的数字余额；每名女仆出生时获得一次初始 100。C 以**个人账户**承担矿场工资责任，其卖矿所得也进 C 的个人账户。公共仓库保存自己的库存与余额（允许在上限内为负）；不能把矿井仓库或任务板仓库直接当作公共仓库。
- 发布采矿合约时明确写下 `数字报酬 R → 目标工分 10R`，工分由新交付物品的**固定原价**累计，报酬按合约给定；不做库存涨跌引起的重新估价。D 做满并退出矿井、MQ 验收后立即记账 `C余额 -= R，D余额 += R`，即使 C 因此负债，D 也已经拿到钱；负债的 C 倾向优先售矿、还款。
- 制作订单消耗材料的固定贩售价值合计为 `M` 时，成品的基础售价为 `1.2M`，制作人工费为 `0.2M`。配方有多个输出时需按该批实际产出分摊；多订但未用的物品留作库存。材料是按统一原价还是公共仓库固定售价报价、人工费由谁支付以及如何与收购价／售价衔接，均待讨论。
- 公共仓库的主要职责是**调拨现货并疏通资金**，不是要求所有产出都先出售。订单缺材料时优先查它的可用库存；C 为工资、缺工具补货等支出准备资金时，先计算缺口，再从矿场物资中挑选**未为其他订单预留、且超出本地必要库存**的部分出售。出售多少以及何时停卖以补足资金需求为界，不能为了变现抢走已承诺的矿石或无限倾销。
- 矿场售矿：矿井库存减少，公共仓库**当场买断并付款**，记账 `公共仓库余额 -= 收购价，C余额 += 收购价`；售出的矿物成为公共仓库商品。其他女仆买货：公共仓库交货并收费，记账 `买家余额 -= 售价，公共仓库余额 += 售价`。收购价／售价与透支额度仍待确定；初始 100 在女仆账户，不等于仓库自带启动金，因此仓库允许有限负余额以启动第一笔收购。
- 上述每笔交易都要把物品流转与金额变化对应起来，并防止重复收货、重复付款或重复发工资。负余额是账户债务：D 已拿到工资，不再另记一笔“C 欠 D 的工资”。报价来源、不同账户的信用边界和自动还债策略见 §7。

## 6. 已替代的旧方案与 MaidTown 后续接入

以下记录设计演变，**不是与 §2 并行生效的规则**：

- 旧设想是女仆自行租矿井场地与工具，矿物归本人；因此曾讨论女仆预付工具使用额度、按耐久扣款并退余款。**该付费工具方案已由“矿场供工具并承担成本、产物归矿场、矿工领工分工资”取代**；石镐价值 10／铁镐价值 50 等旧示例不再是当前工具收费规则。
- 曾讨论让 MaidTown 上线后才处理货币；现改为 **MQ+MMW 阶段就需实现数字余额、工资、公共仓库买卖与有限透支**。MaidTown 后续可扩展居民的生活需求、财产及定价策略，但不是眼下经济循环的前置模组。
- 矿场的公共库存与矿工的个人余额可以同时存在；管理女仆出售矿场物资后获得货款，同时以自己的个人余额承担矿工工资。将来更完整的个人／公共产权规则需要在交易、职务变更等边界处补全。
- 部分物品订单的交付物由任务板暂时代管；托管期间的法律所有权、取消委托如何退回、完成后如何过户仍未最终确定。MaidTown 原设计的“贡献点”和本方案 MQ 数字货币是否相同，也仍需讨论（见 [SPEC.md §8](SPEC.md#8-贡献点经济系统)）。

## 7. 接下来要讨论的问题

1. **固定原价、交易与流动性**：已定“基础产物手工定价、合成产物按配方推导”，公共仓库不按库存调价且作为中转站优先供给缺料者；尚需确定具体基础价、特殊物品定价，以及仓库收购价与售价是否同为原价或存在**固定**差价。制作材料价、多输出配方与 `1.2M` 的取整规则是什么？仓库有限透支／收购容量耗尽又暂时无人购买时，矿场如何应对资金缺口而不假称已经保证永不受阻？
2. **个人负债与管理职务**：C 欠款后优先还债的具体调度规则是什么？C 换岗、死亡或矿井拆除时个人债务和她代售矿场物资的权限如何处理？工种开关关闭时已接劳动合约怎样安全交接？其他女仆买货是否也可欠款、出生赠金如何确保只发一次尚未确定。
3. **固定原价工分与合约边界**：招募单目标为 `10R` 工分、矿工交货按物品固定原价计分、无产物工序不给分已定；交货超出目标时如何处理剩余工分或产物，以及如何防止矿井物资反复取存刷分？矿井没挖到原料但劳动合约都完成时，C 何时补招或报告订单受阻？死亡清零已定，其余强制中断（如取消、收起、矿井消失）的结算待定。
4. **个人物品暂存与矿场库存**：入矿时个人物品存在哪里，工作中新增的私人物品怎样区分，退出／死亡／矿井拆除后如何取回？矿井现有清货规则会保留部分火把／垫脚且不存镐，后续须确认工具归还与仓库出入库边界。
5. **任务板、制作工资与生产调度**：A 的父订单等待材料时是否始终保留给 A？同一女仆可持有多少等待中的订单？公共仓库有现货时，由谁先购买、支付不足怎么办、如何把现货运到工作台并防止重复预留？应急工具单怎样取得优先级？制作人工费 `0.2M` 由发布者、上游订单委托方还是公共仓库支付，制作女仆何时收到？任务板的物品托管、取消与领取怎样避免重复计算？
6. **备货目标与行为倾向**：工作台允许预订多于当前配方所需的材料、矿井 C 常驻招募 3～5 份合约的目标库存／工作量由谁决定？委托倾向开启／关闭时，接单、自主工作、有限备货之间如何选，实际执行如何互斥？TLM 原生女仆面板是否提供扩展按钮的可用入口？
7. **配方与矿井补给**：示例中的“铁矿石”究竟是哪一种熔炉输入？配方有多条时如何选择，燃料与木棍怎样计算？缺工具请求如何决定最小可行的木镐／石镐、与已有或在途工具订单去重？
8. **MaidTown 兼容**：原 GDD 的贡献点是否与 MQ 数字货币共用，未来的私人产权与矿场公有产物如何衔接？哪些价目和需求由 MaidTown 提供新的策略，而不覆盖 MQ 已经存在的工资／仓库交易账？

## 8. 建议的验证切片（实施顺序待确认）

1. 先验证 TLM 委托倾向、工种／工作站资格筛选、父单挂起和按单托管：玩家要木镐 → A 发布木材单 → E 砍树交木材 → A 领取并制作木镐 → 玩家收到成品；无单时有限备货。
2. 验证矿场角色和劳动合约：C 发布报酬 `R`、目标 `10R` 工分的合约 → D 入矿暂存私物、使用矿场工具、上交新采集的产物按价值记分 → 达标退出取回私物 → MQ 一次性从 C 账户给 D 发工资；缺工具和满背包均不结束合约，死亡无本单工资。
3. 验证公共仓库收购／售出与数字账本：女仆各有初始 100，仓库有限透支当场收购矿产，C 在工资负债时优先售矿，其他女仆购买物品并回补仓库余额。
4. 接入 C 的矿井库存领料、结构化缺工具请求与五份固定工分合约，再扩展熔炉制作、煤和铁矿原料，最后跑通本文件 §3 的铁镐根订单。

以上是设计记录和建议的切分方式；实际实现范围、接口与工作顺序仍以接下来的讨论为准。
