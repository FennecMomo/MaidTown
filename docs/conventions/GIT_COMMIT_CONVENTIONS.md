# Git 提交规范

## 提交信息结构

每次提交必须包含中文更新日志，按变更类型分类描述。

### 格式

```
<一行摘要>

## 新增
- 叙述新增的文件或功能

## 修改
- 叙述修改的文件或逻辑

## 删除
- 叙述删除的文件或功能
```

### 规则

1. **摘要行**：一句话概括本次提交的核心目的，格式 `类型: 描述`（如 `修复: 矿道完工火把被误挖`）
2. **分类叙述**：按新增/修改/删除三类分区，没有变更的类别可省略
3. **中文书写**：所有内容使用中文描述
4. **叙述性语言**：用完整语句说明做了什么、为什么做，不要只列文件名
5. **覆盖完整**：每个实际变更项都必须体现在日志中，不遗漏

### 提交类型

| 类型 | 用途 |
|------|------|
| 新增 | 新功能、新文件、新模块 |
| 修改 | 现有功能或逻辑的变更 |
| 删除 | 移除文件、模块或废弃代码 |
| 修复 | 修 bug |
| 重构 | 纯结构优化，不改功能 |
| 优化 | 性能/体验优化 |
| 文档 | 纯文档变更 |
| 发布 | 版本发布提交 |

### 示例

```
template 模块 UI 组件库标准化重命名

## 新增
- 新增 Interface/IListItem 和 Interface/IBar 两个接口，统一列表条目和进度条的契约
- 新增 List/ContentList、ButtonListItem、InputListItem 三个列表组件
- 新增 Bar/ScrollBar 和 StateBar 两个进度/滚动条组件

## 修改
- TerritoryArchiveScreen、TaskListScreen、ColonistInfoScreen 迁移到新组件库
- API.md 同步更新所有重命名后的类名和包路径

## 删除
- 删除 fenneclib 和 maidtown 两个模块中旧的 I_Entry、R_Bar、W_EntryList 等 8 个组件文件
```
