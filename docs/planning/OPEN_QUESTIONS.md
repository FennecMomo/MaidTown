- Q39.3.b 入口来源已确认：产业区域边界上凡是二维地图中可达的通行格都算入口，不靠玩家／建筑模板标记，也不要求居民先走过；因此不设单一入口，多个边界通行格同时可用，实际走哪一个由寻路结果决定。
- Q39.3.b 产业地块表示已确认：产业内的产业地块不像野生地块那样记录高度、表面方块等信息，只记录可达／不可达；后台居民本来就不在产业内部行走，墙体、栅栏之类结构本身即不可达。因此入口＝边界上被标记为可达的格，墙顶／栅栏顶／屋顶等高面格不会成为入口，不需要另设“与地面同层”的限制。
- Q39.3.b 离开返回格已确认：进入时走的是哪个边界可达格就记录该格，离开时从同一个格回到室外地图，不每次重新挑选；该格随“当前所在产业”保存在居民记录里，不新建存储。
- Q39.3.b 入口区域重算时机已确认：入口区域是后台概念，世界破坏只在前台（已加载区域）发生，前台转入后台时入口区域全部重算；因此后台期间入口不会中途变化。助手提出的“记下的入口格突然失效如何兜底”场景不成立，该分支撤销，三种兜底方案均不作定案。
- Q39.3.b 区域重叠与相邻已确认：产业区域之间不允许重叠；两个产业区域相邻时，相邻处的边界格不算入口（排除同时邻接另一个产业区域的格）。推导：贴建且没有其他开口的产业会因此没有任何入口，按既有的不可达处理（原地等待并上报），产业之间需要留出通路或开口；重叠禁止的校验落点接入 Q02／Q10。
- Q39.3.c 实体化落点已确认：前台加载产业区域、要把抽象在产业内的居民实体化时，落在产业中心附近的集合点（中心方块周围的安全格、优先没人占用、多人分散），之后由她自己走向当前行动的使用位置；不采用落在入口内侧，也不以使用对象作落点。推导：行动与使用对象按 Q39.2 与 Q39.1.k 的进度恢复规则续做，对象失效走既有打断机制；安全格判定属技术细化。
- Q39.3.d 可通行口径已确认：按顶层方块属性分类判断，水体可通行（游泳）、树叶／树冠可通行（踩过）；岩浆、仙人掌等危险方块与墙体、栅栏、关闭的门不可通行。具体代价取值与水深、高差的配合属技术细化。
- Q39.3.d 切片粒度与捕获时机已确认：以区块（16×16）为单位，在区块由加载转为卸载时抓取；同一区块再次卸载时整块重抓覆盖，不做差异更新；后台期间不抓取也不刷新。推导：相邻区块抓取时刻不同，接缝一致性归本项后续的高差与连接表示处理。
- Q39.3.d 路网连通口径已确认：路网靠连线表示相通——居民实际走过并走通才形成连线，有连线即表示相通；不用高差门槛否决已有连线（梯子、台阶由走过的连线记录），高差只用于没有连线时的空地通行判断。
- Q39.3.e 后台规则口径已确认：后台与前台使用同一套权重决策与监听重判，社交互动也可在后台发生（双方在二维地图上都有位置，邻近即可发起）；只有涉及世界破坏或建设的作业按需强制加载。2026-10-11 追加确认：后台推进精度与前台相同（逐刻），不另设更粗的后台时步。
